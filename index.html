Module 01 · Foundation

What is Cloud Computing?

Cloud என்றால் என்ன?
⬤ Basic
English

Cloud Computing means renting computers, storage, and software over the internet instead of owning physical hardware. You pay only for what you use, just like electricity — you don't own the power plant, but you get power whenever you need it.

தமிழ்

Cloud Computing என்பது உங்கள் சொந்த கணினி வாங்காமல் இணையத்தில் வாடகைக்கு கணினி, சேமிப்பு, மென்பொருள் பயன்படுத்துவது. மின்சாரம் போல் — நீங்கள் Power Plant வைத்திருக்க மாட்டீர்கள், ஆனால் தேவைப்படும்போது மின்சாரம் கிடைக்கும். அதே போல் Cloud-ல் தேவையான போது Server கிடைக்கும்.

Swiggy / Zomato Example: When Swiggy started, they didn't buy 10,000 servers. Instead they rented servers from AWS. During Diwali when orders spike 10x, they scale up instantly. After festival, scale back down. They only paid for what they used. If they had bought physical servers, 90% would sit idle most of the year — wasted money.

☁ Cloud vs Traditional Infrastructure

Types of Cloud Services 3 Models

IaaS — Infrastructure as a Service
Rent raw servers, networking, storage. You manage OS and apps. Like renting a bare apartment — you bring your furniture. Example: EC2.
PaaS — Platform as a Service
Rent a managed platform to deploy your code. Like renting a furnished apartment. Example: AWS Elastic Beanstalk, Heroku.
SaaS — Software as a Service
Use ready-made software. Like staying in a hotel. Example: Gmail, Zoom, Salesforce.

The real difference between the three is who is responsible for what. As you move from IaaS → PaaS → SaaS, AWS takes over more of the work — and you lose some control in exchange.

What is AWS?

AWS என்றால் என்ன?
⬤ Basic
English

Amazon Web Services (AWS) is the world's largest and most comprehensive cloud platform, owned by Amazon. It offers 200+ services including computing, storage, databases, AI, analytics, security, and more. Companies of all sizes — from startups to Netflix and NASA — use AWS to power their applications.

தமிழ்

Amazon Web Services (AWS) என்பது Amazon நிறுவனம் நடத்தும் உலகின் மிகப்பெரிய cloud platform. இதில் 200-க்கும் மேல் சேவைகள் உள்ளன — கணினி, சேமிப்பு, Database, AI, Security எல்லாமே. Netflix, NASA, Swiggy, Flipkart போன்ற நிறுவனங்கள் AWS-ஐ பயன்படுத்துகின்றன.

Why Netflix uses AWS: Netflix streams 3.3 billion hours of video per month. They use AWS to handle traffic in 190 countries. If a new season of a show drops and 50 million people watch simultaneously, AWS auto-scales to handle it. Netflix doesn't own a single data center — it's 100% on AWS.

AWS Global Infrastructure

Regions · Availability Zones
⬤ Basic
English

Region = A geographic area with multiple data centers (e.g., ap-south-1 is Mumbai). Availability Zone (AZ) = An isolated data center within a Region. Multiple AZs protect against single points of failure. If one AZ catches fire, others keep your app running.

தமிழ்

Region = ஒரு நாட்டிலோ / பகுதியிலோ AWS Data Center இருக்கும் இடம் (உதாரணம்: Mumbai = ap-south-1). Availability Zone = Region-க்கு உள்ளே தனித்தனியான Data Center buildings. ஒரு building தீயில் எரிந்தாலும் மற்றது உங்கள் app-ஐ இயக்கும்.

☁ AWS Global Infrastructure Hierarchy

Chennai User Example: If you're in Puducherry and open an app deployed in ap-south-1 (Mumbai), your request travels ~1300 km — very fast. But if the app were only in us-east-1 (Virginia, USA), the request would travel 13,000 km — 10x slower. That's why choosing the right Region matters!

Module 04 · Compute

EC2 — Elastic Compute Cloud

Virtual Servers on AWS
⬤ Basic → Intermediate
English

EC2 is AWS's virtual machine service. It lets you rent a computer (called an Instance) in the cloud with any OS, CPU, RAM, and storage you need. You can launch it in seconds, use it for an hour or years, and terminate when done. You're only charged for the time it runs.

தமிழ்

EC2 என்பது AWS-இன் Virtual Machine service. Cloud-ல் ஒரு computer (Instance என்று சொல்வார்கள்) வாடகைக்கு எடுக்கலாம். எந்த OS வேண்டும், எவ்வளவு RAM வேண்டும் — நீங்களே தேர்வு செய்யலாம். Seconds-ல் start ஆகும், தேவை இல்லாவிட்டால் stop செய்யலாம். இயங்கிய நேரத்திற்கு மட்டும் பணம் செலுத்த வேண்டும்.

Real Example — Startup: A startup in Chennai builds a Django app. They launch a t3.medium EC2 instance (2 vCPU, 4GB RAM) for ₹2,500/month. When their app is featured in the news and traffic spikes 50x, they launch 10 more instances in minutes. After the spike, they terminate the extras. Total cost: proportional to actual usage.

Security Groups Firewall

English

A Security Group is a virtual firewall for your EC2 instance. It controls which traffic can come IN (inbound) and go OUT (outbound) based on protocol, port, and IP address. By default, all inbound traffic is DENIED.

தமிழ்

Security Group என்பது உங்கள் EC2-இன் virtual firewall. எந்த traffic உள்ளே வரலாம் (inbound), எது போகலாம் (outbound) என்று rules set செய்வது. Default-ஆக எல்லா inbound traffic-ம் BLOCK ஆகும். நீங்கள் explicitly allow செய்ய வேண்டும்.

Module 05 · Storage

S3 — Simple Storage Service

Buckets · Objects · Static Hosting
⬤ Basic → Intermediate
English

S3 is AWS's object storage service. You store files (called Objects) inside containers called Buckets. Think of a Bucket as a folder in the cloud. Each Object gets a unique URL. S3 is infinitely scalable — store 1 file or 1 trillion files with no configuration changes.

தமிழ்

S3 என்பது AWS-இன் file storage service. Bucket என்பது cloud-ல் ஒரு folder போன்றது. அதற்குள் Objects (files) சேமிக்கலாம். Photo, Video, PDF, JSON எதுவும் store செய்யலாம். ஒரு file-ஓ, ஒரு trillion files-ஓ — எந்த setting மாற்றாமல் scale ஆகும்.

Real Example — OTT Platform: An OTT platform (like Hotstar) stores all their movies and shows in S3. A 4K movie = ~100GB. S3 stores it with 99.999999999% (11 nines) durability. The video player fetches from S3 via CloudFront CDN. Users in Chennai, Delhi, Mumbai all get fast stream from the nearest edge location. Cost: ~$0.023 per GB/month (less than 2 rupees per GB).

S3 Concepts Core

Bucket
Global-unique named container. Like a domain name — must be unique across all AWS accounts worldwide. Example: my-company-assets-2024
Object
Any file stored in S3. Max single file = 5TB. Each object has a key (path), value (data), metadata, and a URL.
Static Website Hosting
Host a React/Vue/HTML app directly from S3. No server needed. Enable in bucket settings. Cost = near zero for small sites.
Storage Classes
Standard (frequent), Infrequent Access, Glacier (archive). Automatically move old files to cheaper storage with Lifecycle Rules.
# Create an S3 bucket aws s3 mb s3://my-app-bucket-pondicherry --region ap-south-1 # Upload a file aws s3 cp index.html s3://my-app-bucket-pondicherry/ # Sync a folder (e.g., React build) aws s3 sync ./build s3://my-app-bucket-pondicherry/ --delete # Enable static website hosting aws s3 website s3://my-app-bucket-pondicherry/ \ --index-document index.html \ --error-document 404.html # URL: http://my-app-bucket-pondicherry.s3-website.ap-south-1.amazonaws.com

Module 06 · Storage

EBS & EFS — Block & File Storage

Disks for Your EC2 Instances
⬤ Basic → Intermediate
English

EBS (Elastic Block Store) is a virtual hard disk attached to a single EC2 instance — your OS and app files live here, and it persists even if the instance stops. EFS (Elastic File System) is a shared network drive that many EC2 instances can mount and read/write at the same time, like a shared folder.

தமிழ்

EBS என்பது ஒரு EC2 instance-க்கு மட்டும் இணைக்கப்படும் virtual hard disk — OS, files இதில் சேமிக்கப்படும், instance stop ஆனாலும் data இருக்கும். EFS என்பது பல EC2 instances ஒரே நேரத்தில் mount செய்து பயன்படுத்தக்கூடிய shared network drive — shared folder போன்றது.

Real Example: A media company in Chennai runs 5 EC2 instances behind a load balancer, all rendering video thumbnails. Each instance has its own small EBS root volume for the OS, but all 5 mount the same EFS drive to read shared source video files — any instance can pick up any job because the file storage is shared.

EBS Volume Types Choosing a Disk

gp3 (General Purpose SSD)
Default choice for most workloads — balanced price/performance, independently tunable IOPS.
io2 (Provisioned IOPS)
Highest performance, for demanding databases needing consistent low-latency IOPS.

Cheap, high-throughput — good for big data, log processing, not random access.
Snapshots
Point-in-time backups of an EBS volume, stored in S3 — restore to a new volume anytime.

Create & Attach a Volume CLI

# Create a 20GB gp3 EBS volume aws ec2 create-volume \ --availability-zone ap-south-1a \ --size 20 \ --volume-type gp3 # Attach it to a running instance aws ec2 attach-volume \ --volume-id vol-0abc123 \ --instance-id i-0xyz789 \ --device /dev/xvdf # Take a snapshot backup aws ec2 create-snapshot --volume-id vol-0abc123 --description "daily-backup"

Module 07 · Security

IAM — Identity & Access Management

Users · Groups · Roles · Policies
⬤ Intermediate
English

IAM controls who can access what in your AWS account. Users are people (with username/password + access keys). Groups are collections of users sharing the same permissions. Roles are temporary identities assumed by services or humans. Policies are JSON documents that define what actions are allowed or denied.

தமிழ்

IAM என்பது உங்கள் AWS account-ல் யாருக்கு என்ன permission என்று control செய்வது. Users = மனிதர்கள் (developer, devops). Groups = பல users-ஐ ஒரு team-ஆக வைத்து same permission கொடுப்பது. Roles = EC2 போன்ற services-க்கு temporary permission கொடுப்பது. Policies = JSON-ல் எழுதப்பட்ட permission rules.

Office Building Analogy / அலுவலக உதாரணம்:
• Users = Employees (ஊழியர்கள்) with ID cards
• Groups = "DevOps Team" — all DevOps employees get server room access
• Roles = A contractor badge valid only today (temporary access)
• Policies = The rule book: "Finance team can enter Floor 3 only, 9am-6pm"

🔐 IAM Architecture

Principle of Least Privilege Best Practice

Always grant the minimum permissions needed. A developer who only needs to read S3 should NOT have admin rights. This limits blast radius if an account is compromised.

# Example: Read-only S3 Policy { "Version": "2012-10-17", "Statement": [{ "Effect": "Allow", "Action": [ "s3:GetObject", "s3:ListBucket" // NO s3:DeleteObject, s3:PutObject! ], "Resource": "arn:aws:s3:::my-app-bucket/*" }] }

Module 08 · Security

KMS — Key Management Service

Encryption Keys for Everything on AWS
⬤ Intermediate
English

KMS creates and controls the encryption keys used to protect your data across AWS — S3 buckets, EBS volumes, RDS databases, Secrets Manager secrets, and more. Instead of managing raw key files yourself, you define a Key Policy (who can use the key) and AWS handles the encryption/decryption behind the scenes.

தமிழ்

KMS என்பது உங்கள் data-ஐ பாதுகாக்க பயன்படும் encryption keys-ஐ create செய்து control செய்யும் — S3, EBS, RDS, Secrets Manager எல்லாவற்றிலும். Key file-ஐ நீங்களே manage செய்ய வேண்டாம்; Key Policy மூலம் யார் key பயன்படுத்தலாம் என்று சொன்னால் போதும், AWS பின்னால் encryption/decryption செய்யும்.

Real Example: A healthcare startup in Chennai must encrypt patient data at rest for compliance. They create a Customer Managed Key in KMS, use it to encrypt their RDS database and S3 upload bucket, and restrict the key policy so only their backend application's IAM role can decrypt — even an AWS admin without that permission cannot read the raw data.

Key Concepts Fundamentals

AWS Managed Key
Free, automatically created by AWS services (e.g. aws/s3) — simplest option, less control.
Customer Managed Key (CMK)
You create and fully control it — set rotation, define exactly who can use/manage it.
Key Policy
A resource-based policy on the key itself controlling which IAM principals can encrypt/decrypt.
Envelope Encryption
KMS encrypts a small "data key" which then encrypts your actual data — fast and scalable.

Create & Use a Key CLI

# Create a customer managed key aws kms create-key --description "prod-app-encryption-key" # Encrypt a small piece of data (e.g. a config value) aws kms encrypt \ --key-id alias/prod-app-key \ --plaintext fileb://secret.txt \ --output text --query CiphertextBlob # Enable automatic yearly key rotation aws kms enable-key-rotation --key-id alias/prod-app-key

Module 09 · Networking

VPC — Virtual Private Cloud

Subnets · Internet Gateway · Private Network
⬤ Intermediate
English

A VPC is your own isolated network inside AWS. Like a private gated apartment complex with its own roads, security, and rooms. Within a VPC, you create Subnets — smaller network segments. Public subnets have internet access. Private subnets are completely isolated from the internet — perfect for databases.

தமிழ்

VPC என்பது AWS-ல் உங்களுக்கு மட்டும் சொந்தமான private network. ஒரு gated apartment complex போல் — உள்ளே தனி roads, security, rooms உள்ளது. VPC-க்கு உள்ளே Subnets உருவாக்கலாம். Public Subnet = internet-உடன் இணைக்கப்பட்டது (web servers). Private Subnet = internet இல்லாமல் isolated (databases, backend).

🕸️ VPC Architecture — 3-Tier Web Application

Bank Security Model: Your app's database (RDS) lives in a Private Subnet — no internet access AT ALL. Hackers can't reach it directly. The web server in the Public Subnet talks to the DB through internal network. This is exactly how banks secure their core banking systems. The ATM (public) talks to the backend (private), but internet users can't reach the backend directly.

Module 10 · Database

RDS — Relational Database Service

PostgreSQL · MySQL · Backups · Multi-AZ
⬤ Intermediate
English

RDS is a fully managed relational database service. AWS handles installation, patching, backups, and replication. You focus on your data, not the DBA work. Supports PostgreSQL, MySQL, MariaDB, Oracle, SQL Server. Multi-AZ creates a synchronous standby replica in another AZ for automatic failover within ~60 seconds.

தமிழ்

RDS என்பது AWS நிர்வகிக்கும் database service. நீங்கள் database install செய்ய வேண்டாம், backup எடுக்க வேண்டாம் — AWS எல்லாம் செய்யும். PostgreSQL, MySQL போன்ற databases support செய்கிறது. Multi-AZ = ஒரு AZ-ல் database fail ஆனால் மற்றொரு AZ-ல் உள்ள copy 60 seconds-ல் active ஆகும்.

Hospital System Example: A hospital's patient records database uses Multi-AZ RDS. If the primary database in AZ-1a has a hardware failure at 2am, AWS automatically promotes the standby in AZ-1b within 60 seconds. Doctors can still access patient records. Without Multi-AZ, the hospital system would be down until an engineer fixes the hardware — potentially hours. For critical systems, Multi-AZ is non-negotiable.

Module 11 · Database

Aurora — Cloud-Native Database

MySQL & PostgreSQL Compatible, Built for AWS
⬤ Intermediate
English

Aurora is AWS's own cloud-native relational database, compatible with MySQL and PostgreSQL — so existing tools and code work unchanged. It's built on distributed storage that auto-scales up to 128TB, delivers up to 5x MySQL throughput, and supports up to 15 low-latency read replicas. Short answer: they solve overlapping problems, but ALB is not "just Nginx in the cloud." Nginx (used as a reverse proxy) sits in front of your app servers and forwards requests — that's genuinely similar to what a Load Balancer does. But ALB is a fully managed AWS service, while Nginx is software you install, configure, patch, and scale yourself.

Cloud Concepts
Q1. A company currently buys physical servers upfront, sized for their busiest day of the year, even though that peak only happens once a year. Which cloud characteristic solves this problem?
A) High availability
B) Elasticity
C) Multi-factor authentication
D) Data redundancy
Answer: B — Elasticity. Elasticity means capacity automatically grows and shrinks with real demand, so the company pays for peak capacity only when it's actually needed, instead of owning idle servers year-round.
Cloud Concepts
Q2. Which AWS Cloud pricing benefit is described as "trading capital expense for variable expense"?
A) You still pay large upfront costs, just spread monthly
B) You stop buying data centers and instead pay only for what you consume
C) You get free servers for the first year
D) You must commit to a 3-year contract
Answer: B. Instead of large upfront capital expenditure (CapEx) on hardware, you pay AWS a variable operating expense (OpEx) based on actual usage — one of AWS's six core advantages of cloud computing.

Q3. Which deployment model keeps some workloads on a company's own on-premises data center while running others on AWS?
A) Public cloud
B) Private cloud
C) Hybrid cloud
D) Multi-cloud
Answer: C — Hybrid cloud. Hybrid connects on-premises infrastructure with AWS, often used during a gradual migration or when certain data must legally stay on-site.

Q4. Under the AWS Well-Architected Framework, which pillar focuses specifically on stopping and recovering from failures automatically?
A) Cost Optimization
B) Reliability

Answer: B — Reliability. The Reliability pillar covers a system's ability to recover from infrastructure or service disruptions and automatically scale to meet demand.

A) Auto Scaling Groups

Answer: B. AWS's global footprint of Regions and Edge Locations lets you deploy close to users anywhere in the world in minutes — "go global in minutes" is one of AWS's stated cloud advantages.
Security & Compliance
Q6. Under the AWS Shared Responsibility Model, who is responsible for patching the underlying hypervisor that runs EC2?
A) The customer
B) AWS
C) A third-party auditor
D) Both equally, split 50/50
Answer: B — AWS. AWS is responsible for "security OF the cloud" (hardware, hypervisor, physical facilities). The customer is responsible for "security IN the cloud" (OS patches, data, IAM configuration, network settings on their own resources).

Q7. Which of these is considered a security best practice for the AWS account root user?
A) Use the root user for daily administrative tasks
B) Share the root credentials with the whole DevOps team
C) Enable MFA on it and avoid using it for everyday work
D) Disable it entirely so no one can ever log in
Answer: C. AWS recommends enabling multi-factor authentication (MFA) on the root user, locking away its credentials, and creating individual IAM users/roles for daily work instead.
Security & Compliance
Q8. A company needs to give an application running on EC2 permission to read from an S3 bucket, without storing any long-term access keys on the instance. What should they use?
A) An IAM user with an access key stored in the app's code
B) An IAM role attached to the EC2 instance
C) The account root user's credentials
D) A public S3 bucket policy allowing anyone access
Answer: B — IAM role. Roles provide temporary, automatically-rotated credentials to an EC2 instance — the recommended way to grant AWS service-to-service permissions, avoiding hardcoded long-term keys entirely.
Security & Compliance
Q9. Which AWS service centrally records every API call made in an account, including who made it and when, for audit purposes?
A) Amazon CloudWatch
B) AWS CloudTrail

D) Amazon Inspector
Answer: B — CloudTrail. CloudTrail logs API activity (the "who did what, when") for governance and audit. CloudWatch, by contrast, focuses on operational metrics and performance monitoring.
Security & Compliance
Q10. What is the principle of least privilege?
A) Giving every user AdministratorAccess so nothing is ever blocked
B) Granting only the exact permissions a user or service needs to do its job, nothing more
C) Rotating passwords every 90 days
D) Encrypting all data at rest
Answer: B. Least privilege means starting with zero access and adding only the specific permissions required — reducing the damage possible if credentials are ever compromised.
Security & Compliance
Q11. Which AWS service would you use to centrally store and automatically rotate a database password used by an application?
A) AWS Secrets Manager
B) Amazon S3
C) AWS Trusted Advisor
D) Amazon Route 53
Answer: A — Secrets Manager. It securely stores secrets like DB credentials and can automatically rotate them on a schedule, unlike S3 (object storage) or Route 53 (DNS).

Q12. A company needs a database that can flexibly store JSON-like records at massive scale with single-digit millisecond latency, and doesn't need complex SQL joins. What should they choose?
A) Amazon RDS

D) Amazon EFS

Q13. Which storage class in S3 is most cost-effective for data that is rarely accessed but must be retrievable within minutes if needed?
A) S3 Standard
